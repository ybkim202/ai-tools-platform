# AITools — 기획 · UX/UI 검토

> 작성일: 2026-05-31 · 점검 범위: `frontend/src`(7화면·네비·상태·API) + `docs/PROJECT_OVERVIEW.md` 갭 분석 교차 검증
> 성격: (1) 레포에 없던 **기획 골격(Persona·Pain·Solution)을 코드에서 역산해 정리**하고, (2) **이미 구현된 IA·User Flow를 그 기준으로 평가·피드백**하는 균형 문서.
> 우선순위 원칙: 실제 코드 > PROJECT_OVERVIEW(진단) > 기타 문서. 본 문서는 기획-UX 단일 출처를 지향한다.

## TL;DR

- **무엇인가**: AI 도구를 탐색·비교·추천받고 트렌드를 훑는 무인증 풀스택 웹. 7개 화면(홈·비교·추천·뉴스·깃헙트렌드·벤치마크·상세)이 end-to-end로 구현됨.
- **기획 공백**: 레포에 명시적 페르소나·User Story·Pain/Solution 정의가 없다. "무엇을 만들었나"는 코드로 명확하나 "누구의 어떤 문제를 왜 이렇게 푸는가"가 문서로 고정돼 있지 않다 → 본 문서가 그 골격을 채운다.
- **UX 현주소**: **구현 완성도는 높다.** 일관된 EmptyState 3종, 모바일 카드 스택, 접근성(aria-live·색비의존·키보드 네비)이 7화면에 공유됨. 플로우(검색/필터·비교·추천·온보딩)는 끊김이 거의 없다.
- **데이터 현주소**: 추천(태그 19개·tool_tags≈312)·벤치마크(24행)는 **점등 완료**, 뉴스·깃헙트렌드는 **수집 파이프라인 완비·cron 수집 실행 시 점등**(초기 0행). 이제 빈 화면 리스크는 운영 트리거(prod 부트스트랩·수집)로 좁혀졌다.
- **핵심 피드백(F1~F7, F8 드롭)**: 네비 위계 평탄화(F1)·운영 점등(F2)·전역 검색(F3)·결과 비교 동선(F4)·Hero CTA(F5)·가치 카피(F6)·홈 검색 디바운스(F7)는 **이번 세션에 대부분 구현 완료**. F8("쉬운 시작점")은 **드롭** — 입문자 전용 큐레이션 대신 "트렌드를 계속 확인하는 사이트"라는 가치를 F5/F6 트렌드 메시징으로 흡수.

## 1. User Persona & User Story

명시 페르소나 문서가 없어, 실제 구현 신호(추천 탭=업무별/직업별, 난이도 필터, 무인증, 트렌드·뉴스 소비형 화면)에서 역산했다. **추론이며 사용자 확인이 필요한 가설**이다.

| # | 페르소나 | 한 줄 정의 | User Story | 코드 근거 |
|---|----------|------------|------------|-----------|
| **P1** | 도구 탐색 입문자 | AI 도구가 너무 많아 뭘 써야 할지 모르는 실무자 | *"As a 마케터, I want 내 직무에 맞는 도구를 추천받아 후보를 좁히고 싶다."* | `Recommendations.jsx`(업무/직업 탭), Home 카테고리·난이도 필터 |
| **P2** | 비교 의사결정자 | 후보 2~5개를 두고 근거로 고르려는 사람 | *"As a 개발자, I want 후보 도구를 가격·난이도·벤치마크로 나란히 비교하고 싶다."* | `Compare.jsx`(최대 5개 테이블), `Details.jsx` |
| **P3** | 트렌드 추적자 | 최신 도구·뉴스를 빠르게 훑는 얼리어답터 | *"As a 얼리어답터, I want 깃헙 트렌드·뉴스로 최신성을 확인하고 싶다."* | `GithubTrends.jsx`, `News.jsx` |
| **P4** | AI FOMO를 느끼는 현대인 | 전문가는 아니지만 "남들 다 쓰는 AI를 나만 놓치는 듯한" 불안을 가진 일반 사용자. 깊은 비교보다 "지금 뭐가 핫한지·뭐부터 써보면 되는지"를 가볍게 확인하고 싶다 | *"As a AI에 뒤처질까 불안한 직장인, I want 부담 없이 지금 뜨는 AI 도구·트렌드를 훑고, 입문 난이도가 낮은 것부터 시작하고 싶다."* | 무인증 즉시탐색, 난이도 필터, GithubTrends·News의 가벼운 소비형 화면 |

> **P4의 전략적 의미**: P1~P3은 "이미 목적이 있는" 사용자다. P4는 **목적이 모호한 채 불안만 있는** 대중층으로, 잠재 트래픽이 가장 크다. P4의 FOMO를 짧게 충족시켜(지금 핫한 것 + 쉬운 시작점) P1/P2 동선으로 끌어올리는 것이 전환 설계의 핵심이다.

## 2. User Pain Points

| # | Pain Point | 누가(주 페르소나) | 근거 |
|---|------------|-------------------|------|
| **PP1** | 정보 과잉/탐색 비용 — 도구는 많은데 "내 직무" 기준 진입점이 없다 | P1 | 추천 탭 구조, 난이도/카테고리 필터 존재 |
| **PP2** | 객관 비교 불가 — 가격·성능·난이도가 사이트마다 흩어져 나란히 못 본다 | P2 | Compare 테이블(가격·사용자수·벤치마크 행) |
| **PP3** | 최신성/FOMO — 지금 뭐가 뜨는지 모르고, "남들 다 쓰는데 나만 뒤처지는" 불안 | P3·P4 | GithubTrends(주간/월간), News(트렌딩/최근) |
| **PP3b** | 시작점 부재 — FOMO는 있으나 "입문 난이도 낮은 무엇부터" 써볼지 모른다 | P4 | 난이도 필터·관련 도구·추천(점등 완료). 단, 전용 큐레이션 대신 트렌드 가치로 흡수(F8 드롭) |
| **PP4** | 진입 장벽 — 회원가입·결제 없이 즉시 보고 싶다 | 전체 | 로그인/계정 시스템 부재(무인증 SPA) |

## 3. Solution — 제품이 각 Pain을 어떻게 푸는가

**Pain ↔ 화면 매핑.** "현재 동작 여부"를 함께 표기한다(추천·벤치마크는 점등 완료, 뉴스·깃헙트렌드는 수집 파이프라인 완비·수집 실행 시 점등).

| Pain | 솔루션 화면/기능 | 현재 동작 | 비고 |
|------|------------------|-----------|------|
| PP1 | Home 검색·카테고리·난이도 필터 + Recommendations(업무/직업) | 탐색·필터 ✅ / **추천 점등 완료**(태그 19개·tool_tags≈312) | 빈 결과는 여전히 `coming_soon` 분기로 graceful |
| PP2 | Compare(최대 5개 나란히) + Details(가격·벤치마크·뉴스·관련도구) | 비교 ✅ / **벤치마크 점등 완료**(24행, LLM 9개) | 비교 테이블·모바일 카드 스택 완성 |
| PP3 | News(트렌딩·최근 30일) + GithubTrends(주간/월간) + Benchmarks | 벤치마크 ✅ / **뉴스·깃헙트렌드는 수집 파이프라인 완비·cron 수집 실행 시 점등**(초기 0행) | 깃헙 트렌딩은 한글/영문 병기·테마 필터까지 구현 |
| PP3b | 난이도 필터 + Details 관련 도구 + 추천 | 난이도 필터 ✅ / 추천·관련도구 점등 완료 | "쉬운 것부터" 전용 큐레이션은 채택 안 함(트렌드 가치로 흡수) |
| PP4 | 무인증 SPA(즉시 탐색, 계정 불필요) | ✅ 완전 동작 | 진입 마찰 최소화는 명확한 강점 |

> **요지**: 골격(P2 비교·P4 무인증·P1 탐색)과 **차별 가치(추천·벤치마크)는 점등 완료**. 뉴스·깃헙트렌드는 코드·수집 파이프라인이 완비됐고 **잔여는 운영 트리거(수집 cron 실행)** 뿐이다. UX 관점의 함의는 4·6장에서 다룬다.

## 4. IA (Information Architecture) — 현행 + 평가

### 현행 글로벌 네비게이션

```
🤖 AITools(홈) | 홈 · 비교[뱃지N] · 추천 · 트렌드▾(뉴스·깃헙트렌드) · 벤치마크 | 🌙다크모드
                                                          └ 모바일: 햄버거(ESC·바깥클릭 닫힘)
푸터: 브랜드 / 탐색 링크(비교·추천·뉴스·깃헙트렌드·벤치마크·GitHub) / © 2026
```

7화면 위계: **3개 1차 동선**(홈·비교·추천) + **트렌드 그룹**(뉴스·깃헙트렌드) + **벤치마크** + 상세(`/details/:id`, 카드 클릭으로만 진입).

### 강점 (유지할 것)

- **무인증 즉시탐색** — 홈 진입 = 바로 도구 그리드. PP4를 구조적으로 해결.
- **트렌드 드롭다운 그룹핑** — 뉴스·깃헙트렌드를 의미 단위로 묶어 최상위 항목 폭주를 막음.
- **비교 뱃지** — 선택 도구 수를 네비에 노출해 진행 중 비교 상태를 항상 가시화.
- **일관 패턴의 7화면** — EmptyState 3종(NoData/Filtered/Error)·LoadingState, 데스크톱 테이블↔모바일 카드 스택, 접근성(`aria-live` 공지·`aria-pressed` 토글·색에 비의존·키보드 네비)이 모든 화면에 공유됨. 신규 화면 추가 시 재사용 가능한 **디자인 시스템 수준의 일관성**.

### 개선 피드백

- **F1 — 네비 위계 재배치 구현.** 이번 세션에 App.js 네비/푸터 순서를 홈→추천→비교(뱃지)→트렌드▾→벤치마크로 재배치해 가치 축을 앞세웠다. 트렌드 중심 가치 메시징도 함께 반영. (잔여: 시각적 강조 미세조정은 후속 디자인 합의 영역)
- **F2 (운영) — 데이터 점등은 완료, 잔여는 운영 트리거다.** 추천·벤치마크 데이터는 점등 완료(bootstrap.py가 schema→tools→tags→benchmarks를 멱등 적재). 뉴스·깃헙트렌드는 코드·수집 파이프라인 완비·초기 0행이라 **cron 수집(.github/workflows/collect.yml, 매일 00:00) 실행 후 점등**된다. 따라서 이 항목은 "노출 전략 설계"가 아니라 **운영 점등(prod Render DB 부트스트랩 + 수집 cron 가동) 확인**으로 reframe된다. [미확정] prod(Render) DB의 실적재·cron 첫 수집 여부는 라이브 확인 필요.
- **F3 — 전역 검색 구현 완료.** 이번 세션에 헤더 전역 검색(`components/GlobalSearch.jsx`, 300ms 디바운스 타입어헤드, `searchTools` limit 6, 항목→`/details/:id`, Enter→`/?search=q`) 추가로 어느 화면에서든 즉시 검색 가능. (기존: Home에만 존재 → 해소)

## 5. User Flow — 현행 + 평가

> 표기 규칙: 각 단계는 **트리거(사용자 행동)** → **시스템 반응** → **상태/영속** → **다음 분기**로 읽는다.
> 🟢=정상 경로, 🟡=마찰/개선 지점(F#), 🔵=분기(빈 결과·에러·엣지).

### 5.0 전체 동선 지도 (페르소나 → 목표)

```
                    ┌──────────────────────────────────────────────────┐
   진입(/) ─Hero─►  │  HOME: 검색·카테고리·난이도·정렬 + 도구 그리드     │
                    └──────────────────────────────────────────────────┘
                       │ 카드클릭        │ 비교담기(≤5)     │ Footer CTA
                       ▼                 ▼                  ▼
                 ┌───────────┐     ┌──────────┐      ┌─────────────┐
   P1/P2 ──────► │ DETAILS    │◄───┤ COMPARE   │      │ RECOMMEND   │ ◄── P1
                 │ 가격·벤치   │     │ 2~5 나란히 │      │ 업무/직업탭  │
                 │ ·뉴스·관련  ├────►│           │      └──────┬──────┘
                 └─────┬──────┘ 담기 └──────────┘  🟢 F4 결과→비교(CompareTray)
                       │ 비교토글/관련도구              │ 결과 ToolCard
                       └───────────────────────────────┘ (Details·비교 담기)
   P3/P4 ──Hero보조CTA(🟢 F5 "지금 뜨는 AI 보기")──► NEWS · GITHUB TRENDS · BENCHMARKS
                                       (소비형: 외부링크/Details 이동)
```

페르소나별 "성공 경로(happy path)":
- **P1 입문자**: 진입 → (추천 탭=업무/직업 선택) → 추천 결과 → Details → *비교 담기* → Compare → 공식사이트. **🟢 F4 해소**: 추천 페이지에 CompareTray가 있어 결과에서 Compare로 바로 넘어갈 수 있음.
- **P2 의사결정자**: 진입 → 검색/필터로 후보 탐색 → 카드마다 비교 담기(≤5) → Compare 테이블 → 도구명 클릭으로 Details 왕복 → 결정.
- **P3 추적자**: 진입 → 트렌드▾(뉴스/깃헙) → 카드 소비 → 외부(GitHub/출처) 또는 Details.
- **P4 FOMO**: 진입 → **🟢 F5 해소** Hero 보조 CTA "지금 뜨는 AI 보기"로 트렌드 직행 → 깃헙트렌드/뉴스 소비. (입문자 전용 시작점 PP3b는 트렌드 가치 메시징으로 흡수 — F8 드롭.)

### 5.1 온보딩 플로우

| # | 트리거 | 시스템 반응 | 상태/영속 | 분기 |
|---|--------|-------------|-----------|------|
| 1 | `/` 진입 | Hero(배지·제목·부제) + CTA "도구 탐색하기 ↓" 렌더 | `getMeta()`로 카테고리·난이도 동적 로드 | 🔵 meta 실패 → 필터 비활성, 그리드는 로드 시도 |
| 2 | CTA 클릭(또는 스크롤) | `#tools` 앵커로 smooth scroll | — | — |
| 3 | 그리드 자동 로드 | `getTools()` 21개/페이지 | LoadingState 스켈레톤 | 🔵 0건(필터無)=EmptyNoData / 실패=ErrorState(재시도) |
| 4 | 목록 하단 도달 | Footer CTA "도구 비교"·"맞춤 추천" 노출(목록 있을 때만) | — | 🟢 **F5/F6 해소**: Hero에 "지금 뜨는 AI 보기"(트렌드)·"도구 비교" 보조 CTA + 트렌드 중심 가치 카피 반영 |

🟢 진입 마찰이 낮고(무인증·즉시 그리드) Hero→탐색 연결이 명확. Hero 보조 CTA·트렌드 가치 카피로 P4 동기부여까지 보강됨(F5/F6).

### 5.2 검색/필터/정렬 플로우 (정합성 良)

| # | 트리거 | 시스템 반응 | 상태/영속 | 분기 |

### 개선 피드백 (Flow)

- **F4 — 결과 페이지 비교 동선 구현 완료.** 이번 세션에 `components/CompareTray.jsx`(useUIStore 자립 구독 공용 비교 트레이)를 도입해 Home·Recommendations에 적용. 추천으로 후보를 좁힌 P1이 그 자리에서 Compare로 넘어갈 수 있다(P1→P2 다리 연결). (기존: Home 전용 Tray → 해소)

## 6. 종합 평가 & 개선 우선순위

### 강점 / 약점

**강점** — UI 구현 완성도·일관성이 높다(EmptyState/로딩/모바일/접근성 패턴 공유). 무인증 즉시탐색으로 진입 마찰이 낮다. 비교·검색/필터·추천 플로우가 끊김 없이 설계됨.
