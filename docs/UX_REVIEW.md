# AITools — 기획 · UX/UI 검토

> 작성일: 2026-05-31 · 점검 범위: `frontend/src`(7화면·네비·상태·API) + `docs/PROJECT_OVERVIEW.md` 갭 분석 교차 검증
> 성격: (1) 레포에 없던 **기획 골격(Persona·Pain·Solution)을 코드에서 역산해 정리**하고, (2) **이미 구현된 IA·User Flow를 그 기준으로 평가·피드백**하는 균형 문서.
> 우선순위 원칙: 실제 코드 > PROJECT_OVERVIEW(진단) > 기타 문서. 본 문서는 기획-UX 단일 출처를 지향한다.

## TL;DR

- **무엇인가**: AI 도구를 탐색·비교·추천받고 트렌드를 훑는 무인증 풀스택 웹. 8개 화면(홈·**소개(About)**·비교·추천·뉴스·깃헙트렌드·벤치마크·상세)이 end-to-end로 구현됨(+404 폴백).
- **기획 공백**: 레포에 명시적 페르소나·User Story·Pain/Solution 정의가 없다. "무엇을 만들었나"는 코드로 명확하나 "누구의 어떤 문제를 왜 이렇게 푸는가"가 문서로 고정돼 있지 않다 → 본 문서가 그 골격을 채운다.
- **UX 현주소**: **구현 완성도는 높다.** 일관된 EmptyState 3종, 모바일 카드 스택, 접근성(aria-live·색비의존·키보드 네비)이 7화면에 공유됨. 플로우(검색/필터·비교·추천·온보딩)는 끊김이 거의 없다.
- **데이터 현주소**: 추천(태그 19개·tool_tags≈312)·벤치마크(24행)는 **점등 완료**, 뉴스·깃헙트렌드는 **수집 파이프라인 완비·cron 수집 실행 시 점등**(초기 0행). 이제 빈 화면 리스크는 운영 트리거(prod 부트스트랩·수집)로 좁혀졌다.
- **핵심 피드백(F1~F7, F8 드롭)**: 네비 위계 평탄화(F1)·운영 점등(F2)·결과 비교 동선(F4)·Hero CTA(F5)·가치 카피(F6)·홈 검색 디바운스(F7) 구현 완료. **F3 전역 검색(헤더 타입어헤드)은 구현했다가 제거**(접근성 이점 대비 가치 낮음 — PR #42). 검색 진입점은 홈 검색/필터로 일원화. F8("쉬운 시작점")은 **드롭** — 입문자 전용 큐레이션 대신 "트렌드를 계속 확인하는 사이트"라는 가치를 F5/F6 트렌드 메시징으로 흡수.

## 1. User Persona & User Story

명시 페르소나 문서가 없어, 실제 구현 신호(추천 탭=업무별/직업별, 난이도 필터, 무인증, 트렌드·뉴스 소비형 화면)에서 역산했다. **추론이며 사용자 확인이 필요한 가설**이다.

| # | 페르소나 | 한 줄 정의 | User Story | 코드 근거 |
|---|----------|------------|------------|-----------|
| **P1** | 도구 탐색 입문자 | AI 도구가 너무 많아 뭘 써야 할지 모르는 실무자 | *"As a 마케터, I want 내 직무에 맞는 도구를 추천받아 후보를 좁히고 싶다."* | `Recommendations.jsx`(업무/직업 탭), Home 카테고리·난이도 필터 |
| **P2** | 비교 의사결정자 | 후보 2~5개를 두고 근거로 고르려는 사람 | *"As a 개발자, I want 후보 도구를 가격·난이도·벤치마크로 나란히 비교하고 싶다."* | `Compare.jsx`(최대 5개 테이블), `Details.jsx` |
| **P3** | 트렌드 추적자 | 최신 도구·뉴스를 빠르게 훑는 얼리어답터 | *"As a 얼리어답터, I want 깃헙 트렌드·뉴스로 최신성을 확인하고 싶다."* | `GithubTrends.jsx`, `News.jsx` |
| **P4** | AI FOMO를 느끼는 현대인 | 전문가는 아니지만 "남들 다 쓰는 AI를 나만 놓치는 듯한" 불안을 가진 일반 사용자. 깊은 비교보다 "지금 뭐가 핫한지·뭐부터 써보면 되는지"를 가볍게 확인하고 싶다 | *"As a AI에 뒤처질까 불안한 직장인, I want 부담 없이 지금 뜨는 AI 도구·트렌드를 훑고, 입문 난이도가 낮은 것부터 시작하고 싶다."* | 무인증 즉시탐색, 난이도 필터, GithubTrends·News의 가벼운 소비형 화면 |

> **P4의 전략적 의미**: P1~P3은 "이미 목적이 있는" 사용자다. P4는 **목적이 모호한 채 불안만 있는** 대중층으로, 잠재 트래픽이 가장 크다. P4의 FOMO를 짧게 충족시켜(지금 핫한 것 + 쉬운 시작점) P1/P2 동선으로 끌어올리는 것이 전환 설계의 핵심이다.

## 2. User Pain Points

| # | Pain Point | 누가(주 페르소나) | 근거 |
|---|------------|-------------------|------|
| **PP1** | 정보 과잉/탐색 비용 — 도구는 많은데 "내 직무" 기준 진입점이 없다 | P1 | 추천 탭 구조, 난이도/카테고리 필터 존재 |
| **PP2** | 객관 비교 불가 — 가격·성능·난이도가 사이트마다 흩어져 나란히 못 본다 | P2 | Compare 테이블(가격·사용자수·벤치마크 행) |

| **PP4** | 진입 장벽 — 회원가입·결제 없이 즉시 보고 싶다 | 전체 | 로그인/계정 시스템 부재(무인증 SPA) |

## 3. Solution — 제품이 각 Pain을 어떻게 푸는가

**Pain ↔ 화면 매핑.** "현재 동작 여부"를 함께 표기한다(추천·벤치마크는 점등 완료, 뉴스·깃헙트렌드는 수집 파이프라인 완비·수집 실행 시 점등).

| Pain | 솔루션 화면/기능 | 현재 동작 | 비고 |
|------|------------------|-----------|------|
| PP1 | Home 검색·카테고리·난이도 필터 + Recommendations(업무/직업) | 탐색·필터 ✅ / **추천 점등 완료**(태그 19개·tool_tags≈312) | 빈 결과는 여전히 `coming_soon` 분기로 graceful |
| PP2 | Compare(최대 5개 나란히) + Details(가격·벤치마크·뉴스·관련도구) | 비교 ✅ / **벤치마크 점등 완료**(24행, LLM 9개) | 비교 테이블·모바일 카드 스택 완성 |
| PP3 | News(트렌딩·최근 30일) + GithubTrends(주간/월간) + Benchmarks | 벤치마크 ✅ / **뉴스·깃헙트렌드는 수집 파이프라인 완비·cron 수집 실행 시 점등**(초기 0행) | 깃헙 트렌딩은 한글/영문 병기·테마 필터까지 구현 |
| PP3b | 난이도 필터 + Details 관련 도구 + 추천 | 난이도 필터 ✅ / 추천·관련도구 점등 완료 | "쉬운 것부터" 전용 큐레이션은 채택 안 함(트렌드 가치로 흡수) |
| PP4 | 무인증 SPA(즉시 탐색, 계정 불필요) | ✅ 완전 동작 | 진입 마찰 최소화는 명확한 강점 |

> **요지**: 골격(P2 비교·P4 무인증·P1 탐색)과 **차별 가치(추천·벤치마크)는 점등 완료**. 뉴스·깃헙트렌드는 코드·수집 파이프라인이 완비됐고 **잔여는 운영 트리거(수집 cron 실행)** 뿐이다. UX 관점의 함의는 4·6장에서 다룬다.

## 3.5 About 페이지 — 설득 아크로 재구성(2026-07)

`/about`(네비 '소개')은 신규 방문자(특히 P4)를 추천/탐색으로 전환시키는 **설득 페이지**다. 리서치(Linear·Notion·Raycast·Stripe / 2026 clarity-led minimalism)의 결론 — *모든 섹션은 하나의 일을 하고, 추상 일러스트 대신 구체(실 데이터/UI)로 주장을 증명한다* — 을 반영해, 기존 "페르소나 4카드 + Pain→답 타임라인"이 **같은 상황→기능 매핑을 두 번 반복**하던 중복을 제거하고 **훅→문제→해결→이게 나?→왜 믿나→행동** 아크로 재구성했다.

| 순서 | 섹션 | 조직 원리 | 내용 |
|------|------|------|------|
| ① **Hero(2단)** | 훅+증명+전환 | 좌: 한 줄 정의 + 신뢰 메타(`total_tools`개+·카테고리·가입불필요·광고랭킹아님) + **CTA 1개** / 우: **실데이터 "나란히 비교" 미니 뷰**(`AboutCompareVisual` — 리스트로 난이도 다양성 최대 카테고리 선택 → `compare` 엔드포인트로 실 가격·난이도·인기 3×3). 데이터 없으면 1단 복귀 |
| ② **문제 한 컷** | 공감(문제만) | 대형 임팩트 타이틀 + pain 키워드 칩 3개(정보 과잉·객관 비교 부재·최신성 불안). 링크 없음 |
| ③ **어떻게 돕나(3스텝)** | **기능 중심** | 탐색→비교→추천 핵심 루프. 번호(01/02/03)+아이콘+설명+링크. 탐색 스텝에 실 도구 수 주입. 커넥터 라인, 스크롤 순차 등장 |
| ④ **누구에게(라우터)** | **사람 중심** | P1~P4 컴팩트 카드 — 자기식별→시작점(추천·탐색·뉴스·트렌드). ③보다 가볍게 |
| ⑤ **왜 믿나** | 증거·이견해소 | 라이브 수치(count-up) + "무인증"·"광고랭킹 아님(사용자수·벤치마크 기준)" |
| ⑥ **클로징 CTA** | 전환 | 1차 "맞춤 추천"(솔리드) + 2차 "전체 도구 탐색"(고스트) |
| + **Sticky CTA** | 상시 전환 | Hero 이탈 후 상시 "맞춤 추천"(모바일 thumb-zone) |

**③↔④ 중복 차단**: ③=기능 중심(무엇을 한다, 가로 번호 스텝) / ④=사람 중심(당신이라면 어디서 시작, 컴팩트 카드). 시각도 분리. **타임라인 제거**(pain은 ②로 압축, 링크는 ③·④가 흡수).

> **IA 최신화(2026-07)**: 구 링크(`/recommendations`·`/compare`·`/`=둘러보기)가 재설계된 목적지(`/#recommend`·`/explore`)를 안 가리키던 부패를 정정. 비교는 도구 선택이 선행돼야 하므로 `/explore`로 유도(빈 모달 회피).

**디자인/트렌드**: 신규 섹션은 `glass-soft`·spacing/radius/font 토큰만 재조합(신규 색토큰 0·인라인 hex 0), 배경 리듬 교차(문제 surface / 3스텝 background / 페르소나 surface / 증거 background). 반영 트렌드 = clarity-led minimalism·구체(실 데이터/UI)로 주장 증명·스크롤 순차 등장·마이크로 인터랙션(count-up·hover)·sticky CTA. 접근성: 진입·count-up `prefers-reduced-motion` 폴백(즉시 노출/최종값), IO 미지원·데이터 실패 graceful, 각 섹션 `aria-labelledby`, sticky 비노출 시 `tabIndex=-1`+`aria-hidden`.

**전환 측정(이벤트 추적)**: 각 CTA 클릭을 **자체 백엔드 이벤트**로 적재(`POST /api/events`, 키 없는 1st-party, IP/UA 미수집). `trackEvent('about_cta_click', {target, path})`는 fire-and-forget. target = `hero_recommend` · `how_explore`·`how_compare`·`how_recommend`(3스텝) · `persona_p1~p4` · `closing_recommend`·`closing_explore` · `sticky_recommend`(문제 섹션은 링크 없음). → 어느 스텝·페르소나 진입이 전환을 끄는지 사후 분석.

> **서사 일관성 주의**: ③·④가 보내는 `/news`·`/trends/github`는 수집 cron 점등 전 0행이다(F2). 직후 빈 상태가 신뢰를 깎지 않도록 **운영 점등 우선** 또는 각 페이지 EmptyState 품질에 의존.

## 4. IA (Information Architecture) — 현행 + 평가

### 현행 글로벌 네비게이션

```
🤖 AITools(로고=홈) | 소개 · 추천 · 비교[뱃지N] · 트렌드▾(뉴스·깃헙트렌드) · 벤치마크 | 🌙다크모드
                                                          └ 모바일: 햄버거(ESC·바깥클릭 닫힘)
푸터: 브랜드 / 탐색 링크(비교·추천·뉴스·깃헙트렌드·벤치마크·GitHub) / © 2026
```

8화면 위계: **소개(About)** + **2개 1차 동선**(추천·비교) + **트렌드 그룹**(뉴스·깃헙트렌드) + **벤치마크** + 상세(`/details/:id`, 카드 클릭으로만 진입) + 404 폴백(`*`). **텍스트 '홈' 항목은 제거** — 홈 복귀는 헤더 브랜드 로고로 일원화하고, 첫 네비 자리를 '소개'에 내줘 신규 방문자에게 제품 서사를 먼저 제시(3.5장).

### 강점 (유지할 것)

- **무인증 즉시탐색** — 홈 진입 = 바로 도구 그리드. PP4를 구조적으로 해결.
- **트렌드 드롭다운 그룹핑** — 뉴스·깃헙트렌드를 의미 단위로 묶어 최상위 항목 폭주를 막음.
- **비교 뱃지** — 선택 도구 수를 네비에 노출해 진행 중 비교 상태를 항상 가시화.
- **일관 패턴의 7화면** — EmptyState 3종(NoData/Filtered/Error)·LoadingState, 데스크톱 테이블↔모바일 카드 스택, 접근성(`aria-live` 공지·`aria-pressed` 토글·색에 비의존·키보드 네비)이 모든 화면에 공유됨. 신규 화면 추가 시 재사용 가능한 **디자인 시스템 수준의 일관성**.

### 개선 피드백

- **F1 — 네비 위계 재배치 구현.** App.js 네비/푸터 순서를 가치 축으로 재배치하고, 이후 텍스트 '홈' 항목을 **'소개(About)'로 대체**해 현재 **소개→추천→비교(뱃지)→트렌드▾→벤치마크** 순이다(홈 복귀는 로고). 신규 방문자가 첫 항목에서 제품 서사(3.5장)를 만난다. 트렌드 중심 가치 메시징도 함께 반영. (잔여: 시각적 강조 미세조정은 후속 디자인 합의 영역)
- **F2 (운영) — 데이터 점등은 완료, 잔여는 운영 트리거다.** 추천·벤치마크 데이터는 점등 완료(bootstrap.py가 schema→tools→tags→benchmarks를 멱등 적재). 뉴스·깃헙트렌드는 코드·수집 파이프라인 완비·초기 0행이라 **cron 수집(.github/workflows/collect.yml, 매일 00:00) 실행 후 점등**된다. 따라서 이 항목은 "노출 전략 설계"가 아니라 **운영 점등(prod Render DB 부트스트랩 + 수집 cron 가동) 확인**으로 reframe된다. [미확정] prod(Render) DB의 실적재·cron 첫 수집 여부는 라이브 확인 필요.
- **F3 — 전역 검색: 구현 후 제거.** 헤더 타입어헤드(`GlobalSearch.jsx`)를 추가했으나, 접근성 이점이 크지 않아 제거(PR #42). 검색 진입점은 **홈 검색/필터로 일원화**하고, 백엔드 검색 범위를 이름→**이름·설명·카테고리·태그**로 확장(`tools.py`)해 홈 검색의 발견성을 보강. (`/?search=q` 딥링크 흡수는 홈에 유지)

## 5. User Flow — 현행 + 평가

> 표기 규칙: 각 단계는 **트리거(사용자 행동)** → **시스템 반응** → **상태/영속** → **다음 분기**로 읽는다.

페르소나별 "성공 경로(happy path)":
- **P1 입문자**: 진입 → (추천 탭=업무/직업 선택) → 추천 결과 → Details → *비교 담기* → Compare → 공식사이트. **🟢 F4 해소**: 추천 페이지에 CompareTray가 있어 결과에서 Compare로 바로 넘어갈 수 있음.
- **P2 의사결정자**: 진입 → 검색/필터로 후보 탐색 → 카드마다 비교 담기(≤5) → Compare 테이블 → 도구명 클릭으로 Details 왕복 → 결정.
- **P3 추적자**: 진입 → 트렌드▾(뉴스/깃헙) → 카드 소비 → 외부(GitHub/출처) 또는 Details.
- **P4 FOMO**: 진입 → **🟢 F5 해소** Hero 보조 CTA "지금 뜨는 AI 보기"로 트렌드 직행 → 깃헙트렌드/뉴스 소비. (입문자 전용 시작점 PP3b는 트렌드 가치 메시징으로 흡수 — F8 드롭.)

## 8. 핵심 지표 1개 승격 — 정보구조 재설계 (2026-06 · `/wiki-ux-plan`)

### 8.1 핵심 설계 원칙 — 전 화면 공유 "강조 문법"

핵심 지표 **1개에만** 크기↑ + 잉크 강조색 + (선택)글리프를 부여하고 나머지는 회색 메타로 강등한다. 승격 **축 자체는 "카드 ⊆ 상세 ⊆ 비교"에서 동일(=인기)** — 깊이 들어갈수록 신호가 *추가*될 뿐 축이 바뀌지 않아 멘탈모델이 끊기지 않는다. Benchmarks는 다른 렌즈(성능)지만 **같은 강조 문법**을 재사용한다. (근거: wiki [[ui-디자인-실무-컨펌-체크리스트-라인-계층-정보우선순위]] §5, [[ux-전환-심리-ab-테스트-페이월-가격표시-부킹]] B evaluative ease, [[ui-디자인-기초-시그니파이어-위계-타이포-색-다크모드-상태]] B/E/F)

### 9.3 큐레이션 기준 (데이터 정합성)

커버리지가 달라 단일 기준이 불가하다:
- **인기(user_count)**: 거의 모든 도구 보유 → **모든 용도에서 Top N 가능**(기본 기준).
- **성능(benchmarks)**: LLM ~9개만 보유 → 대부분 카테고리에서 부재. **데이터가 있는 용도에만 "성능" 배지/탭 보조 제공**(없는 곳에 만들지 않음 — 빈 결과·거짓 신호 금지, 헌법 G3/G5).

→ 결정: **인기 기본 + 성능 보조**. 묶음 축 = **카테고리**(모든 도구 보유, 안정적)로 Top 섹션 구성, **직업/업무(task)는 통합 추천 토글**로.

### 9.4 화면별 스펙(요약)

**랜딩 `/`**
- 히어로: 간결한 가치 1줄 + 단일 1차 진입(검색 또는 "전체 탐색"). 과밀 금지.
- 큐레이션 섹션: DB 카테고리(하드코딩 금지, `/tools/meta`·count 기준 상위 N개 카테고리) 각각 **인기 Top 5** 미니 카드(로고·이름·인기 지표 승격, 성능 배지는 데이터 있을 때만) + "이 용도 전체 보기 →"(=`/explore?category=`).
- 추천 통합: "용도별(기본) / 직업별" 토글 — 직업별은 recommendations API로 직군 Top 큐레이션.
- 전역 CTA: "모든 도구 탐색 →"(`/explore`).
- "카드 ⊆ 상세 ⊆ 비교" 일관 + 핵심 지표 1개 승격(§8) 그대로 적용.

**추천 통합**: `/recommendations` → 랜딩 토글로 흡수. 기존 경로는 랜딩(직업별 모드)으로 리다이렉트(공유 링크 보존).

- 마무리(완료): `/leaderboard` = 전체 인기 랭킹 유지. 네비 슬림화 — **추천·비교는 상단 네비에서 제외**(추천=랜딩 #recommend·용도 칩, 비교=카드 버튼·트레이·모달로 도달). 최종 네비 = 탐색·랭킹·벤치마크·트렌드▾·소개.

### 9.6 디자인 언어

Artificial Analysis 지향 — 편집된 큐레이션·데이터 기반 랭킹·여백 위계, AI slop 신호(이모지·과밀·중복 KPI) 회피. 신규 색토큰 0, 기존 토큰만(인라인 hex/버튼 pill 금지).

### 9.7 랜딩 고도화 (2026-06, PR #95 — main 머지)

§9.4의 "랜딩 `/`"를 한 단계 더 다듬은 후속 작업. 정보 구조·기준은 9.2~9.3 그대로, **표현·구성**만 강화했다.

- **2단 Hero(`hero--split`)**: 좌측=가치 카피(카테고리별 타이핑 헤드라인)+1차/보조 CTA(좌측정렬·크기 축소), 우측=**큐레이션 위젯**. 배경은 전체폭(잉크 radial 헤일로 ≤0.06 + 도트 그리드, 단일 잉크 유지), 콘텐츠는 1200 그리드.
- **CuratedHeroWidget**(벤치마크 프리뷰형 2단): 좌측 **아이콘 전용 카테고리 레일**(hover 시 이름 핀 확장), 우측 선택 카테고리 인기 Top 5 세로 리스트. **4.5초 자동 회전**(hover/포커스 시 일시정지), 전환 시 fade. 노출 카테고리는 count 상위 7개 — 단 **특수목적·콘텐츠생성·데이터분석은 제외**(전체 탐색엔 존재). 카테고리별 **무채색 라인 아이콘**(이모지 금지)·**헤드라인 카피**는 `utils/categoryMeta.js` 정본.
- **타이핑 헤드라인**: 자동 회전과 동기. 카피는 `\n`으로 줄바꿈 고정(`white-space: pre-line`) + 2줄 min-height로 흔들림/CLS 방지. `prefers-reduced-motion`이면 즉시 표시(완성 텍스트는 `aria-label`).
- **섹션 순서**: Hero → **맞춤 추천** → **깃헙 트렌드 프리뷰** → **벤치마크 프리뷰** → Footer CTA.
- **깃헙 트렌드 프리뷰(GithubTrendTeaser)**: 주간 급부상 오픈소스 Top 4를 랜딩에 임베드(전체 `/trends/github`). **0행이면 미렌더**(BenchmarkTeaser와 동일 정직성, G3).
- **맞춤 추천 패널 개선**: 업무별/직업별을 **칩 좌측 단일 토글**(기본 업무별→클릭 시 직업별)로 통합, 각 업무·직업 칩에 아이콘, 칩 선택 시 **화면 이동 없음**(결과만 갱신). 결과 카루셀은 한 화면 **정확히 4개**(태블릿 2·모바일 1, 잘림 없음).
- **일관 토큰화**: 랜딩 주요 섹션 간격 `{spacing.5xl}` 96px(신설), 섹션 제목 전부 24px 통일 + 제목 아래 한 줄 소제목, 글래스모피즘 2티어(strong/soft) 정리. 상세는 [DESIGN.md](./DESIGN.md) "Glassmorphism"·Spacing 참조.

### 9.8 탐색(/explore) 퍼싯 재설계 (2026-07, PR #107·#108 — main 머지)

전체 탐색 페이지(ToolBrowser, Explore 전용)를 faceted-search 표준으로 재구성. 정보구조(IA)는 §9.2 그대로(랜딩=큐레이션, /explore=전체 탐색), **필터 UX**만 강화. 리서치 근거는 faceted search 베스트프랙티스(사이드바·퍼싯 카운트·다중선택·모바일 드로어).

**동기(갭):** 카테고리 20개가 평면 버튼 행으로 결과 위에 쌓여 과밀 · 퍼싯별 개수 없음(0건 예방 불가) · 단일선택 · 로딩 스피너(홈은 스켈레톤).

**구현(단계별):**
- **P0** — 로딩 **그리드 스켈레톤**(홈 스켈레톤 프리미티브 재사용), 카테고리 **목록 내 검색 + 세로 스크롤**로 과밀 해소, 빈결과 회복(EmptyFilteredState·초기화).
- **P1** — 좌측 **퍼싯 사이드바**(데스크톱, surface 카드) / 모바일 **필터 드로어**(오버레이·ESC·스크롤락, `필터(N)` 토글). 퍼싯 그룹 `fieldset/legend`.
- **P2** — **퍼싯 카운트**(백엔드 `/tools/meta` 에 `category_counts`·`difficulty_counts`·`license_counts` 전역 카운트 **가법** 추가). 옵션에 `(N)` 표시 + **0건 비활성**(기대치 설정·빈결과 예방). 카운트 맵 없으면 폴백(미표시·전부 활성).
- **P3** — 카테고리 **그룹 내 OR 다중선택**(백엔드 콤마구분 → `IN`, 정적 placeholder·params 바인딩으로 **SQLi 안전**, 단일값 하위호환). **보기 밀도 토글**(그리드/촘촘히).

**디자인 원칙 연결:** 무채색 캔버스 + 잉크 틴트 활성(색 단독 아님 — `aria-pressed`+텍스트+카운트 숫자 병행), 토큰만(인라인 hex 0). **데이터 정합성 최상위** — 카운트·옵션은 전부 DB 실값(하드코딩 금지 G5/G6), 0건 비활성으로 빈 결과 방치 금지(G3). 접근성 — `fieldset/legend`·키보드·`aria-busy` 스켈레톤. 홈과 **스켈레톤 일관**.

**검증:** Supabase 로컬 백엔드(카운트 정확·다중 IN=20·단일 하위호환) + prod 배포 후 카운트/다중 IN 라이브 확인 + /explore 헤드리스 스크린샷.

**후속(선택):** ① 진짜 단일-컬럼 컴팩트 리스트 뷰(현재는 밀도 토글로 대체), ② "현재 필터 맥락 반영" 카운트(전역 → 조건부).
