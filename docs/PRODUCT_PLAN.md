## 0. 데이터 사실 (이 기획의 전제)

기획의 모든 제안은 아래 "지금 실제로 있는 데이터" 안에서만 한다. (헌법: 데이터 정합성 > 기능)

| 영역 | 현재 상태 | 페이지에서 쓸 수 있나 |
|---|---|---|
| `tools` (name·category·difficulty·user_count·description·official_url·logo_url·country) | 적재됨, 78개 | ✅ 즉시 |
| `category` 20종 / `difficulty` 한글(쉬움·보통·어려움) | 적재됨 | ✅ 필터·배지 |
| `pricing` (plan·price·billing_period·description) | 적재됨 | ✅ 가격 섹션 |
| `tags` (task 11 · profession 8) + `tool_tags` | 적재됨 | ✅ 추천 동작 |
| `recommendations` (`meta.feature_status`) | 동작 | ✅ |
| `compare` | 동작 | ✅ |
| `benchmarks` | **테이블만, 데이터 0건** | ⛔ "준비 중" 처리만 |
| `news` | **테이블만, 데이터 0건** | ⛔ "준비 중" 처리만 |

> 원칙: benchmarks·news에 의존하는 신규 섹션은 **"데이터 적재 시"** 단서를 달고 P2 이하로 둔다. 빈 결과를 가치 섹션으로 위장하지 않는다.

### 모든 페이지 공통으로 발견한 갭 (사실)

- **G-A. 카드 → 상세 진입 동선 없음**: `ToolCard.jsx`의 버튼은 "방문하기"(외부 `official_url`)와 "비교"뿐. `/details/:id`로 가는 내부 링크가 카드/그리드 어디에도 없다. 상세 페이지는 존재하나 **사실상 도달 불가**. → 4개 페이지 기획의 최우선 연결 과제.
- **G-B. 상세 "뒤로가기"가 항상 `/`로 고정**: `Details.jsx`는 `navigate('/')`. 추천/비교에서 들어와도 홈으로 튕긴다. → `navigate(-1)` 권고(구현 판단은 frontend-react).
- **G-C. 비교 담기 동선 단절(G8 연장)**: 카드에서 "비교" 선택은 store에 쌓이나, 사용자가 **비교 페이지로 이동하라는 안내/배지**가 떠 있는 동선이 약함(홈 하단 CTA만 존재).

## 1. 홈 / 탐색 (`/` · Home.jsx)

### 1.1 목적 · JTBD
- **JTBD-1**: "AI 도구가 많은데 뭐가 있는지 일단 훑어보고 싶다" — 전체 카탈로그를 빠르게 스캔.
- **JTBD-2**: "내 카테고리/난이도에 맞는 도구만 좁혀 보고 싶다" — 필터·검색으로 후보를 줄인다.
- **JTBD-3**: "괜찮은 걸 찾으면 더 알아보거나 비교 후보에 담고 싶다" — 상세/비교로 이어간다.

### 1.2 IA · 섹션 (위→아래)

| 순서 | 섹션 | 목적 | 핵심 콘텐츠 | 우선순위 |
|---|---|---|---|---|
| 1 | 히어로 | 제품 한 줄 가치 + 탐색 진입 | 타이틀·서브카피·"도구 탐색하기" 앵커 | P0 (있음) |
| 2 | 검색 + 필터 | 후보 좁히기 | 검색창 / 카테고리(DB 메타) / 난이도(DB 메타) | P0 (있음) |
| 3 | 결과 헤더 | 현재 결과 규모·맥락 | "발견한 도구" + N개 카운트 | P0 (있음) |
| 4 | 도구 그리드 | 스캔·선택 | ToolCard(로고·이름·카테고리·설명·메타·액션) | P0 (있음) |
| 5 | 빈 상태 | 0건 회복 | 필터/검색 변경 안내 + 초기화 | P0 (있음) |
| 6 | 하단 CTA | 비교·추천으로 유도 | "도구 비교" / "맞춤 추천" 링크 | P1 (있음) |

### 1.3 현재 대비 개선 · 추가 (보유 데이터 한정)
- **[P0] 카드에 "자세히" 동선 추가 (G-A)**: ToolCard에 `/details/:id` 진입을 추가. 현재 상세 페이지가 고립돼 있음 — 가장 임팩트 큰 수정. *(구현은 frontend-react)*
- **[P1] 정렬 옵션**: 보유 필드만으로 가능 — 사용자수순·이름순. `getTools`는 이미 params를 받으므로 백엔드 정렬 파라미터 유무 확인 필요(→ backend-fastapi). 없으면 클라이언트 정렬로 시작.
- **[P1] 활성 필터 칩 요약**: 선택된 카테고리/난이도/검색어를 결과 헤더 위에 한 줄로 노출 + 개별 해제. 현재는 필터 영역에만 active 상태가 있어, 스크롤 후 "내가 뭘 걸었는지" 잃기 쉬움.
- **[P1] 비교 담기 가시화 (G-C)**: 카드에서 비교 선택 시 "비교함 N개 · 비교하기" 떠 있는 진입점(예: 그리드 상단 또는 고정 바). 현재는 홈 맨 아래 CTA로만 유도.
- **[P2 · 데이터 적재 시] 트렌딩/신규 섹션**: "지금 뜨는 도구"는 news/벤치마크 또는 수집 시계열이 있어야 의미. 데이터 0건이므로 **만들지 않음**. 대안으로, 보유 데이터만으로 "사용자수 상위 도구" 큐레이션 띠는 가능(P2, 선택).

### 1.4 콘텐츠 우선순위 · 카피 톤
- 우선순위: 검색·필터(행동) > 결과 카운트(맥락) > 그리드 > 하단 CTA.
- 톤: 친근하고 행동 유도형. "발견하세요 / 골라보세요". 과장(최고·1위) 금지 — 객관 데이터(사용자수)로 말한다.
- 빈 상태 카피: 자책 유발 금지. "조건에 맞는 결과가 없어요 → 필터를 바꿔보세요"(현행 유지 적절).

### 1.5 성공 지표 (가벼움)
- 필터/검색 사용률(진입 세션 중 1회 이상 필터 조작 비율).
- 그리드 → 상세 진입률(= G-A 수정 효과 측정), 그리드 → 비교 담기율.
- 빈 상태 도달 후 "초기화" 클릭으로 회복하는 비율.

## 2. 비교 (`/compare` · Compare.jsx)

### 2.1 목적 · JTBD
- **JTBD-1**: "후보 2~5개를 나란히 놓고 한눈에 차이를 보고 싶다" — 항목별 정렬 비교.
- **JTBD-2**: "가격/난이도/규모 기준으로 결정하고 싶다" — 의사결정 근거 확보.

### 2.2 IA · 섹션 (위→아래)

| 순서 | 섹션 | 목적 | 핵심 콘텐츠 | 우선순위 |
|---|---|---|---|---|
| 1 | 페이지 헤더 | 맥락·관리 | 제목 + "선택 N/5" + 초기화 | P0 (있음) |
| 2 | 빈/부분 상태 안내 | 누락 투명화 | 미선택 안내 / 일부 누락 도구명 노출 | P0 (있음) |
| 3 | 비교 표(데스크톱) | 항목별 비교 | 카테고리·난이도·사용자수·가격·벤치마크(준비중)·링크 | P0 (있음) |
| 4 | 비교 카드(모바일) | 좁은 화면 비교 | 동일 항목 세로 스택 | P0 (있음) |

### 2.3 현재 대비 개선 · 추가 (보유 데이터 한정)
- **[P0] 비교 화면 안에서 도구 추가/교체 동선**: 현재 비교는 홈에서 담아야만 채워진다. 비교 페이지에서 빈 슬롯에 도구를 직접 추가(검색→선택)하면 이탈 없이 완성 가능. 보유 `getTools`로 구현 가능. *(실현성 frontend-react)*
- **[P0] 표의 행 라벨에 상세 링크**: 각 도구 헤더(로고·이름)에서 `/details/:id` 진입(G-A 연장). 비교 중 "더 알아보기" 자연스러움.
- **[P1] 차이 강조(보유 데이터로)**: "가격 최저", "사용자수 최다" 같은 비교 내 우위 표시. 데이터로 계산 가능, 주관 평가 아님. 단 색만으로 의미 전달 금지(텍스트 병행 — 헌법).
- **벤치마크 행**: 현행 "준비 중" 처리 유지(데이터 0건). 행 자체는 남겨 **데이터 적재 시 자동 채워지는** 구조 유지가 옳음. 새 가치 약속 카피는 달지 않는다.

### 2.4 콘텐츠 우선순위 · 카피 톤
- 우선순위: 가격 > 난이도 > 사용자수 > (벤치마크 준비중) > 링크. 의사결정 직결 항목(가격·난이도)을 위로.
- 톤: 중립·사실. "어느 게 더 좋다" 단정 금지. 우위 표시는 "이 항목에서 최저/최다" 같은 사실 진술로.
- 부분 누락 안내(현행)는 좋은 패턴 — 유지.

### 2.5 성공 지표
- 비교 완성률(2개 이상으로 표를 실제로 본 세션 비율).
- 비교 → 외부 방문(`official_url`) 또는 상세 진입 전환율.
- 부분 누락 발생률(데이터 정합성 신호 — 높으면 store/ID 동기화 점검).

## 3. 추천 (`/recommendations` · Recommendations.jsx)

### 3.1 목적 · JTBD
- **JTBD-1**: "내 직무/업무에 맞는 도구를 골라주면 좋겠다" — 선택지 과부하 해소.
- **JTBD-2**: "로그인 없이 바로 결과를 보고 싶다" — 즉시성(현행 충족).

### 3.2 IA · 섹션 (위→아래)

| 순서 | 섹션 | 목적 | 핵심 콘텐츠 | 우선순위 |
|---|---|---|---|---|
| 1 | 페이지 헤더 | 맥락 | "나에게 맞는 AI 도구" | P0 (있음) |
| 2 | 탭(업무별/직업별) | 추천 축 선택 | task / profession 전환 | P0 (있음) |
| 3 | 선택지 그리드 | 조건 입력 | DB 태그(task 11·profession 8) 버튼 | P0 (있음) |
| 4 | 결과 그리드 | 추천 결과 | ToolCard 목록 | P0 (있음) |
| 5 | 빈 상태(2분기) | 0건 회복 | 미적재(NoData) vs 해당선택 0건(Filtered) | P0 (있음) |
| 6 | 초기 안내 | 첫 진입 유도 | "선택하면 추천이 표시됩니다" | P0 (있음) |

### 3.3 현재 대비 개선 · 추가 (보유 데이터 한정)
- **[P1] 추천 근거 한 줄**: "이 도구가 왜 추천됐는가" — 선택한 태그와 도구의 매칭 태그를 노출(예: "콘텐츠작성·마케터 태그 일치"). `tool_tags`로 이미 매칭하므로 표시 데이터는 존재. 신뢰·설명가능성↑.
- **[P1] 결과 헤더 맥락**: "'개발자'에게 추천하는 도구 N개"처럼 선택 맥락을 결과 위에 명시. 현재는 "추천 결과"만.
- **[P1] 결과 카드 → 상세/비교 연결 (G-A·G-C)**: 추천 결과에서 바로 상세 보기·비교 담기. 추천은 비교로 가는 자연스러운 깔때기.
- **[P2] 다중 선택 추천**: 현재 단일 태그 선택. 보유 데이터로 2개 태그 교집합 추천이 가능하나, 추천 로직(백엔드) 변경 필요 → backend-fastapi 협의 후 결정. **열린 질문**.
- 톤·구조는 데이터가 실제로 있는 기능이므로 표시·설명 강화에 집중(신규 데이터 의존 금지).

### 3.4 콘텐츠 우선순위 · 카피 톤
- 우선순위: 탭 → 선택지 → (선택 후) 결과 맥락 → 결과 카드.
- 톤: 개인화·안내형. "당신의 업무에 맞는". 결과는 "추천"이지 "정답"이 아님을 카피로 유지(겸손).
- 빈 상태: 현행 2분기(미적재 vs 0건)가 정합성상 정확 — 유지. "준비하고 있어요"는 데이터 적재 전제에서만.

### 3.5 성공 지표
- 선택지 클릭률(진입 → 태그 1개 이상 선택 비율).
- 추천 0건 발생률(낮을수록 태그 커버리지 양호 — tools-data-curator 신호).
- 추천 결과 → 상세/비교/방문 전환율.

## 4. 도구 상세 (`/details/:id` · Details.jsx)

### 4.1 목적 · JTBD
- **JTBD-1**: "이 도구가 정확히 뭐고 나한테 맞는지 깊이 보고 싶다" — 단일 도구 심층.
- **JTBD-2**: "가격이 얼마인지, 쓸 만한지 확인하고 결정하고 싶다" — 가격·근거 확인 후 방문/비교.

### 4.2 IA · 섹션 (위→아래)

| 순서 | 섹션 | 목적 | 핵심 콘텐츠 | 우선순위 |
|---|---|---|---|---|
| 1 | 뒤로가기 | 이전 맥락 복귀 | (현행 `/` 고정 → 개선 필요 G-B) | P0 (있음/개선) |
| 2 | 헤더 | 도구 정체성 | 로고·카테고리·이름·설명·국가·난이도·공식사이트 | P0 (있음) |
| 3 | 가격 | 비용 판단 | plan·price·billing·description 카드 | P0 (있음) |
| 4 | 벤치마크 | 성능 근거 | **데이터 0건 → "준비 중"** | P1(데이터 적재 시) (있음) |
| 5 | 뉴스 | 최신성 | **데이터 0건 → "준비 중"** | P2(데이터 적재 시) (있음) |

### 4.3 현재 대비 개선 · 추가 (보유 데이터 한정)
- **[P0] 진입 동선 자체 확보 (G-A)**: 상세 페이지가 완성도 있게 존재하나 도달 경로가 없음. 홈/추천/비교 카드에서 진입 연결이 **이 페이지 가치의 전제**.
- **[P0] 뒤로가기 맥락화 (G-B)**: `navigate('/')` → `navigate(-1)` 권고. 추천/비교에서 진입 시 홈으로 튕기는 현 동작은 맥락 상실.
- **[P1] 헤더에 "비교 담기" 버튼 (G-C)**: 상세에서 본 도구를 바로 비교 후보로. store 연결만으로 가능.
- **[P1] 태그 노출**: 보유 `tool_tags`로 이 도구의 task/profession 태그를 헤더 근처에 표시 → "이 도구는 어떤 업무/직무용인지" 즉시 전달. 추천과 일관.
- **[P1] 관련 도구**: 같은 category의 다른 도구 N개 카드. 보유 `tools`/`category`로 구현 가능. 비교·재탐색 깔때기.
- **벤치마크·뉴스 섹션**: 현행 "준비 중" 인라인 처리 유지(숨김 금지 패턴 적절). 데이터 적재 전까지 이 섹션을 페이지 가치의 핵심으로 카피하지 않는다.

### 4.4 콘텐츠 우선순위 · 카피 톤
- 우선순위: 정체성(헤더) → 가격(결정 직결) → 벤치마크(있을 때) → 뉴스 → 관련 도구.
- 톤: 정보 전달·신뢰. 설명은 사실 위주, 마케팅 과장 배제.
- "준비 중" 카피: 변명 길게 금지. "아직 검증된 점수가 없습니다"(현행) 수준의 담백함 유지.

### 4.5 성공 지표
- 상세 진입 수(0에서 출발 — G-A 수정 효과의 1차 지표).
- 상세 → 공식사이트 방문 클릭률(핵심 전환).
- 상세 → 비교 담기 / 관련 도구 클릭률(재탐색 깊이).

## 5. 페이지 간 동선 요약 (깔때기)

```
홈/탐색 ──(자세히)──▶ 상세 ──(공식사이트 방문)
   │  └─(비교 담기)──▶ 비교 ◀──(결과 담기)── 추천
   └─(맞춤 추천)─────▶ 추천 ──(자세히)──▶ 상세
```
- 현재 끊긴 간선(우선 복구): **홈/추천/비교 → 상세(G-A)**, **카드 → 비교 가시화(G-C)**, **상세 뒤로가기 맥락(G-B)**.

## 6. 우선순위 한눈에 (Impact/Effort, 추정)

| 항목 | 페이지 | Impact | Effort | 권고 |
|---|---|---|---|---|
| 카드/헤더 → 상세 진입(G-A) | 전체 | 높음 | 낮음 | **즉시(P0)** |
| 상세 뒤로가기 `navigate(-1)`(G-B) | 상세 | 중 | 낮음 | P0 |
| 비교 담기 가시화(G-C) | 홈/추천 | 중 | 중 | P1 |
| 추천 근거 한 줄 | 추천 | 중 | 낮음 | P1 |
| 비교 내 도구 추가/차이 강조 | 비교 | 중 | 중 | P1 |
| 관련 도구·태그 노출 | 상세 | 중 | 중 | P1 |
| 정렬·활성 필터 칩 | 홈 | 중 | 낮음~중 | P1 |
| 다중 태그 추천 | 추천 | 중 | 중(백엔드) | P2(열린 질문) |
| 트렌딩/뉴스/벤치마크 신규 섹션 | 전체 | 높음 | 높음 | **데이터 적재 후** |

> 추정 근거: Impact는 깨진 동선 복구·전환 직결 여부, Effort는 보유 데이터만으로 프론트 변경으로 끝나는지 여부 기준의 **추정**. 정확한 실현성은 frontend-react/backend-fastapi 검토 필요.
